# mini-rag

**一句话**：这是个"教你 RAG 到底怎么工作、每一步值多少钱"的学习项目。

不用装任何东西、不用 API Key、不用联网，clone 下来敲一行命令就能跑。

---

## 先看这个：你可能不懂的名词

不用背，看一遍有个印象就行，后面遇到再回来查。

| 名词 | 大白话解释 |
|---|---|
| **RAG** | 一种让 AI 先"查资料"再回答的做法。因为 AI 脑子里没有你的资料，直接问它会瞎编。先把它该看的资料找出来塞给它，它就能答对。 |
| **检索** | 从一堆资料里"找出最相关的那几段"。就像用 Ctrl+F 搜关键词，但更聪明一点。 |
| **切分（chunk）** | 把长文章剪成一小段一小段。因为 AI 一次看不完全文，只能一段一段喂。 |
| **嵌入（embedding）** | 把一段文字变成一串数字。两段文字意思越接近，这两串数字就越像。 |
| **向量检索** | 靠"意思像不像"来找资料。你说"怎么让机器人记住上次聊的事"，它能找到写着"长期记忆跨会话保存"的那段。 |
| **BM25** | 靠"字一样不一样"来找资料，是老牌的搜索算法。你搜"HNSW"，它就找含"HNSW"的段落。 |
| **混合检索** | 上面两种一起用。 |
| **RRF** | 把两种检索的结果"合并排名"的一种算法。 |
| **Recall@5** | 一份成绩单：正确答案在"前 5 条结果"里出现的比例。越高越好。 |
| **MRR** | 另一份成绩单：正确答案排得靠不靠前。第 1 位是满分 1.0，第 2 位是 0.5，第 5 位是 0.2。 |
| **消融实验** | "把某个零件拆掉，看成绩掉多少"——用来判断这个零件到底有没有用。 |
| **零依赖** | 不用装任何第三方库，Python 自带的就够。 |

---

## 这个项目为什么存在

网上讲 RAG 的文章都会说：

> "用混合检索效果更好。"
> "切分粒度很重要。"

但没人告诉你**在你自己这里到底值多少**。

所以这个项目做了件很朴素的事：准备一批资料和一批问题（带答案），
然后把 RAG 的每个零件拆开，一个一个试，看成绩单上的数字怎么变。

**结果里有一个挺反常识的发现**（见下面"结果"一节）——
这个发现比"混合检索更好"值钱得多。

## 结果

资料：20 篇文档（5 篇长的、15 篇短的，共 3121 字）。
问题：24 个，每个都标好了"正确答案在哪篇文档里"。

### 成绩单一：三种找资料的方法

| 方法 | Recall@5 | MRR |
|---|---|---|
| 向量检索（靠意思像不像） | 87.5% | 0.765 |
| BM25（靠字一样不一样） | **97.9%** | **0.868** |
| 混合检索（两个一起用） | 91.7% | 0.815 |

### 成绩单二：三种剪文章的方法（配上混合检索）

| 方法 | Recall@5 | MRR | 剪成几段 | 最短的一段 |
|---|---|---|---|---|
| 固定长度剪 | 91.7% | **0.875** | 29 | 61 字 |
| 按段落句号剪 | 91.7% | 0.815 | 31 | **10 字** |
| 按章节标题剪 | 83.3% | 0.795 | 35 | 0 字 |

---

## 那个反常识的发现（这是本项目最值钱的部分）

**混合检索反而比只用 BM25 差**（97.9% → 91.7%）。

通常大家说混合检索更好。为什么这里更差？

因为**这个项目里的"向量检索"是个假的**——它其实还是在比字面。
我在项目里用了一个零依赖的简化版嵌入（叫"哈希嵌入"），它只会数"有没有相同的词"，
**完全不懂语义**。

结果就是：两路检索在干同一件事，都是比字面。
合并的时候，反而让噪声把本来排对的结果挤下去了。

**这件事的教训比"混合检索更好"更有用：**

> 混合检索有用的前提，是两个方法"擅长的地方不一样"。
> 如果两个方法都在看同一件事，合在一起只会添乱。

补充一句：换一个真的嵌入模型（懂语义的那种），两路就真的擅长不同的东西了，
那时候混合检索才会有效。代码里留了 `--live` 可以试。

### 从"剪文章"那张表里还能看出一个实用经验

**别只看平均长度，一定要看最短的那段。**

"按段落句号剪"这一列，最短的一段只有 **10 个字**——这就是个碎片，几乎没信息量。
但它会占掉一个候选位置。

结果就是：明明剪得更"聪明"，MRR 反而比最笨的固定长度剪更低（0.815 vs 0.875）。

**碎片是 RAG 里最常见的隐形垃圾。** 这条经验可以直接拿到工作里用。

## 这个项目故意没做什么（诚实说明）

1. **嵌入是假的**。它不懂语义，只数字面。真实项目要换成真的嵌入模型。
2. **没做重排序**。真实项目通常会在最后加一步"精排"，能再涨几个点。
3. **只有 24 个问题，还是我自己编的**。够判断"改动是变好还是变坏"，
   但不足以给出可信的绝对分数。真实项目要从线上真实问题里采样，几百到几千条。
4. **"语义型"问题设计得不够狠**。我本来想设计成"跟原文一个字都不重合"，
   但实际上还是共享了一些词，所以 BM25 也能答对 92.9%。这是我这套题的缺陷。
5. **中文分词很粗糙**。用的是"单字 + 两字组合"，没有真正的分词器，
   所以"贵阳"和"阳贵"会被认为很像。

把这些写出来不是为了显得谦虚，而是因为**知道一个东西的边界在哪，比知道它能做什么更有用**。
